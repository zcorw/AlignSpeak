# 产品需求

## 1. 背景与目标

用户希望在 iPhone 上把一篇文章的 TTS 当作连续音频反复收听，并在 AlignSpeak 内部切页、切换其他 App、锁屏或熄屏后尽可能持续播放。当前实现以段落为单位临时下载 Blob，段落结束后不会自动续播，组件卸载还会主动停止，因此无法支撑该体验。

本功能的目标是：在不引入原生 App 的前提下，为最新稳定版 iOS Safari 提供可预测的整篇准备、站内连续播放、循环、恢复和冲突处理，并用单一整篇媒体尽量降低 iOS 后台环境对 JavaScript 调度和跨音频切换的影响。

## 2. 支持边界

### 2.1 正式支持

- 当前最新稳定版 iOS Safari。
- 普通 Safari 标签页是主要入口。
- 站内路由切换期间保持播放器与下载状态。

### 2.2 兼容验证

- Chrome iOS 运行在 iOS WebKit 约束下，执行核心真机用例。
- 通过验证后可标记“兼容”，但不共享 Safari 的正式 SLA。
- 添加到主屏幕的 PWA 只做兼容性验证，不单独承诺后台可靠性。

### 2.3 明确不承诺

- 不承诺 Web 页面在所有 iOS 版本、内存压力、系统回收、来电或耳机事件下持续后台播放。
- 不承诺 App 被杀或浏览器重开后的离线播放。
- 不申请浏览器通知权限，不使用系统通知表示准备结果。
- 首版不提供原生/Capacitor 壳。

## 3. 核心用户流程

### 3.1 准备与播放

1. 用户从文章列表或练习页点击“准备整篇音频”。
2. 客户端展示预计文件大小；超过 20 MB 时要求确认。
3. 服务端创建或复用幂等准备任务，逐段展示进度。
4. 所有段落准备成功后，服务端发布一个完整的整篇 MP3。
5. 浏览器完整下载音频并提示“可播放”。下载完成前播放按钮不可用。
6. 用户点击播放。播放到文件结尾后，按循环策略重新开始。

### 3.2 失败与重试

- 任一段最终失败，整篇任务进入失败状态，不发布半成品。
- UI 列出失败段落顺序和可理解的错误，不静默跳过。
- “重试”只补失败或缺失段，并复用已成功的分段缓存。

### 3.3 文章变更与手动更新

- 正文、语言、分段顺序、日语读音覆盖、默认音色规则或合成策略变化都会产生新资产版本。
- 旧版本已经播放时允许继续，直到用户停止或选择其他文章。
- 用户下一次点击播放时若发现旧版本，必须先准备最新版。
- 迷你播放器提供“更新音频”：点击即停止并释放旧音频，创建/复用最新版准备任务；新版完整下载后提示用户手动播放。

### 3.4 切换文章

- 浏览器上下文中同时只有一个全局播放器。
- 播放或准备另一篇文章时，若当前文章仍活动，先弹出确认。
- 确认后停止当前音频、清理其内存 Blob，准备并切换新文章。

## 4. 播放规则

- 内容：整篇全部段落，严格按 `segment_order`。
- 音色：沿用当前语言默认音色。
- 语速：固定 1.0。
- 段间停顿：实现值必须落在 500–1000 ms，并作为版本化策略；初始值 750 ms。
- 轮次停顿：实现值必须落在 1000–2000 ms；初始值 1500 ms。
- 默认循环：无限循环，直到用户停止。
- 睡眠选项：本轮结束、15、30、60 分钟。
- 定时停止：按墙上时间计算，暂停期间仍倒计时；到点后保持停止。
- 本轮结束：用户选择后，当前轮播完即停止，不再进入下一轮。

## 5. 恢复与中断

### 5.1 本机恢复

- 保存 `article_id`、`asset_id`、`position_ms`、循环/睡眠状态和 `updated_at`。
- 记录有效期 24 小时，只在资产版本仍匹配时恢复精确秒数。
- 浏览器重开后只显示“恢复”，必须由用户手势真正播放。
- 资产已失效或媒体不可用时清除位置，回到最新版准备流程。

### 5.2 系统与业务中断

- 来电、Siri、耳机断开或浏览器媒体中断后保持暂停，并在站内给出提示；不自动恢复。
- 开始录音前自动暂停整篇音频；录音结束仍保持暂停。
- 单段或单句朗读触发时暂停整篇音频；该朗读结束仍保持暂停。
- 以上暂停不取消睡眠定时器。

### 5.3 多标签页

- 使用跨标签页协调通道和本机租约表达活动播放器所有权。
- 后点击播放的标签页接管；其他标签页收到消息后立即暂停并更新 UI。
- 不能依赖协调消息作为安全边界，服务端资源仍按用户鉴权。

## 6. UI 需求

### 6.1 入口

- 文章列表：准备/播放整篇音频。
- 练习页：准备/播放整篇音频，并保留已有单段与单句朗读。

### 6.2 全局迷你播放器

至少展示：

- 当前文章标题与状态。
- 准备进度（完成段数/总段数）或下载进度。
- 播放/暂停。
- 循环状态与睡眠停止选择。
- 更新音频。
- 失败段信息与一键重试。
- 版本过期、系统中断、其他标签页接管等提示。

### 6.3 通知

- 使用现有站内 Toast/反馈系统。
- 不申请 Web Notification 权限。
- 准备和完整下载完成后只提示用户手动播放，不自动播放。

## 7. 非功能需求

- 用户隔离：媒体访问必须校验整篇资产属于当前用户，不能只验证“已登录”。
- 原子性：只有完整、可探测时长的文件才能进入 `ready` 并对外返回。
- 幂等性：相同输入、音色、语速、停顿与编码版本只生成一份有效资产。
- 可恢复性：API/Worker 重启后任务不丢，超时租约可安全重试。
- 可观测性：能定位任务、失败段、重试次数、合并耗时、文件大小和版本。
- 容量：所有不超过 20,000 字符的合法文章都可准备；需要配额、TTL 和孤儿文件清理。
- 兼容：不依赖 `navigator.connection` 判断蜂窝网络；不依赖后台 JavaScript 定时切换分段。

## 8. 验收场景

1. 全文准备成功、完整下载后才能播放，并按预期停顿无限循环。
2. 锁屏、熄屏、切换 App 时在支持的 iOS Safari 环境尽可能继续，控制中心可播放/暂停；中断时状态可解释且不自动恢复。
3. 任一段失败时整篇不可播放，重试成功后无需重做已缓存段。
4. 站内切页不丢失准备、下载、播放和计时状态。
5. 24 小时内同资产可精确恢复，过期或版本变化不误用旧秒数。
6. 两个标签页竞争时最后播放者接管，前一个暂停。
7. 录音、单段、单句播放都能暂停整篇播放器。
8. 正文/读音变化后旧音频可继续本次播放，但下一次播放强制最新版；“更新音频”立即停止旧版。
9. 预计文件超过 20 MB 时必须确认，取消后不创建准备任务。
