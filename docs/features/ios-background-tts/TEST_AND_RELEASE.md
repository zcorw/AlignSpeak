# 测试与发布计划

## 1. 自动化测试

### 1.1 后端单元测试

- 数据模型约束、唯一键、级联/删除行为。
- 任务幂等创建、所有权过滤和当前资产查询。
- Worker 原子领取、租约心跳、过期回收、重试上限和并发竞争。
- 输入哈希稳定性及正文、读音、停顿/编码版本变化后的失效。
- 分段缓存命中/缺失/失败以及只补失败段。
- FFmpeg 命令输入转义、显式停顿、原子发布、ffprobe 元数据解析。
- 全局时间轴偏移、单调性、范围和长分段跨 chunk 回归。
- 媒体资源所有权、路径约束、Range 请求和文件缺失。
- 清理任务不删除活动资产、可重试删除孤儿文件。

### 1.2 后端集成测试

- 创建任务到 Worker 完成再下载媒体的完整链路。
- API/Worker 重启后任务恢复。
- 两个 Worker 竞争同一任务只发布一份资产。
- 任一段失败时不发布半成品，重试复用已成功段。
- 20,000 字符边界文章可进入流程（供应商调用使用 stub）。

### 1.3 前端测试

- 全局播放器状态机的合法/非法转换。
- 准备轮询、失败段展示、重试、下载完成门禁。
- 大于 20 MB 的确认，取消时不创建任务。
- 文章切换确认和“更新音频”立即停止旧资产。
- 路由切换不销毁播放器。
- 无限循环、本轮结束、15/30/60 分钟墙上时间计时。
- 24 小时精确位置恢复与过期/资产失效清除。
- `BroadcastChannel` 与 storage 回退的最后播放者接管。
- Media Session play/pause action 和不支持环境降级。
- 录音、单段、单句播放时的 audio focus 协调。
- Blob URL 在切换、更新、注销和卸载时释放。

## 2. 必跑命令

实现任务需要按改动范围执行，最终至少包括：

```powershell
docker compose run --rm api pytest -q
docker compose run --rm api python -m compileall app
docker compose run --rm web_v2 yarn lint
docker compose run --rm web_v2 yarn build
```

如果 Compose 服务名与仓库实际配置不同，以验证后的等价命令为准，并在 `TODOLIST.md` 的执行记录中更新。前端新增测试框架后还必须运行其 test 命令。

## 3. 媒体验证

用固定小样本和多段样本检查：

- `ffprobe` 结果为 24 kHz、mono、目标码率附近。
- 时长大于所有段内容时长之和，并包含预期静音。
- 段间停顿初始为约 750 ms，末尾约 1500 ms。
- Safari 可 seek，Range 返回 206 和正确 Content-Range。
- 最终文件不是临时半文件，重复请求字节一致。

## 4. iOS 真机矩阵

正式发布前在发布时最新稳定 iOS 上执行。真实设备验证属于发布门禁，但平台行为结果必须如实记录，不得把“尽力而为”写成硬保证。

| 客户端 | 入口 | 核心场景 |
| --- | --- | --- |
| Safari | 普通标签页 | 准备、完整下载、播放、锁屏、熄屏、切 App、控制中心、来电/耳机中断、恢复 |
| Chrome iOS | 普通标签页 | 准备、下载、播放、锁屏/切 App、控制中心、恢复 |
| Safari PWA | 主屏幕 | 启动、站内切页、播放、锁屏/切 App、恢复 |

每次记录：设备型号、iOS 版本、浏览器版本、开始时间、文章/资产 ID、各场景结果、系统是否回收页面、缺陷链接。

## 5. 发布步骤

1. 部署数据库兼容 schema 和 API，但保持前端入口关闭。
2. 部署带 FFmpeg/ffprobe 的 Worker 和共享媒体卷。
3. 运行健康检查和一篇小文章的合成 smoke test。
4. 开启内部用户功能开关，观察任务失败率、耗时、磁盘和旧 API 回归。
5. 执行 iOS Safari 真机矩阵。
6. 逐步扩大 Web 入口；Chrome/PWA 只有通过对应矩阵后才标记兼容。

## 6. 观测指标

- 整篇任务 queued/processing/done/failed 数量与耗时分位数。
- 分段缓存命中率、分段重试数、失败段分布。
- FFmpeg 合并失败、ffprobe 失败和原子发布失败。
- 资产大小、磁盘总量、清理数量和清理失败。
- API 任务轮询错误、媒体 403/404/410/Range 响应。
- 前端准备取消、超过 20 MB 确认、下载失败、恢复成功和跨标签页接管。

## 7. 回滚

- 前端功能开关关闭整篇入口，不影响现有单段/句子 TTS。
- Worker 停止领取新任务，已处理记录保留供排查。
- API 保留读取已有资产的兼容窗口；不能在仍有客户端使用时立即删除文件。
- 数据表为新增表，回滚应用时不自动 drop。
- `edge-tts` 升级若出现回归，可单独回退，但已生成资产按其版本继续只读。

## 8. 完成标准

- `TODOLIST.md` 全部实施项标记 `[x]`。
- 后端完整测试、前端测试/lint/build、Compose 配置解析和媒体 smoke test 通过。
- 安全审查确认不能跨用户获取整篇媒体。
- 文档与实际 API、表和配置一致。
- 真机门禁有可复现的执行记录；环境暂时无法提供设备时，代码交付可完成，但发布状态必须保持“待真机验证”。
