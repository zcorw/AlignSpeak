## 一句话方案

复用现有分段 TTS 缓存，由持久化 Worker 逐段补齐后使用 FFmpeg 合成为一个带显式停顿、版本化且可鉴权的整篇 MP3；前端只维护一个全局 `HTMLAudioElement`，完整下载后由用户手势开始循环播放。

## 已冻结的关键决策

1. 正式支持当前最新稳定版 iOS Safari；Chrome iOS 做核心真机兼容验证，通过后标记兼容，但不共享 Safari SLA；主屏幕 PWA 仅尽力而为。
2. 切换 App、锁屏、熄屏和控制中心播放/暂停均为优化目标，不承诺 Web 无法稳定保证的后台 SLA。
3. 播放范围固定为整篇全部段落，按 `segment_order` 排序；段间停顿 0.5–1 秒，轮次间停顿 1–2 秒。
4. 整篇生成成功并完整下载后才允许播放。任一段失败就阻止播放，展示失败段并允许一键重试，绝不静默跳过。
5. 固定现有语言默认音色与 1.0 倍速；首版只提供播放/暂停、循环状态和睡眠停止。
6. 默认无限循环，可选择本轮结束或 15/30/60 分钟停止；定时器按现实时间倒计时，暂停期间也继续。
7. 练习页与文章列表都可发起准备；站内切页期间由全局迷你播放器保持状态。
8. 本机保存文章、资产版本和精确秒数 24 小时；重开后必须由用户点击恢复，不自动播放，也不承诺离线重开。
9. 同一浏览器只允许一个活动播放器，后发起播放的标签页接管；录音、单段或单句朗读会暂停整篇音频，结束后仍需手动恢复。
10. 文章内容或读音覆盖变化时，已经在播放的旧音频可继续至用户停止；下一次播放必须准备最新版。另提供“更新音频”按钮，点击后立即停止旧音频并准备新版。
11. 蜂窝网络可使用；开始准备前展示预计文件大小，预计超过 20 MB 时二次确认。不依赖浏览器网络类型探测。
12. 沿用文章 20,000 字符上限，所有合法文章都必须能进入整篇准备流程。
